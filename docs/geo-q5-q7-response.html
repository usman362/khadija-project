Q5 — Professional Service Origin

Preference on the table (not locked): one dedicated Service Origin per Professional account. Travel radius is measured from it. It is not automatically the billing address.

Location fields that exist today

There is one address block on the Professional account. There is no billing street, no map coordinates, no travel radius, and no Service Origin field.

On the request (not the Professional): a free-text location (“city, venue, or address”) plus a two-letter event state. Same-state matching uses the event state. Miles cannot be calculated from free text.

Recommendation (pending stamp — not a schema lock). Create a dedicated Service Origin. Do not reuse the business street as the travel-radius origin, and do not treat it as billing (billing street is not in this product). Keep state as the same-state gate. Keep city and ZIP for display, directory counts, and ZIP fallback. V1 needs only one active origin: one account is already one state; a second state is a second account; no live workflow needs two dispatch bases on the same account. Exact new field names are not proposed here.

NEED MORE INFORMATION (do not assume): default travel radius in miles and whether the Professional may edit it; whether the origin street is shown publicly or used only for distance math; confirmation that Service Origin may differ from the verified business address (recommended: yes).

Q6 — Distance calculation for matching

Preference on the table (not locked): straight-line / geodesic for marketplace search and matching. Driving distance, travel time, and travel fees can be a later feature.

TopicDeveloper answer
StackThe live product is Laravel on PHP, with MySQL in production and SQLite in tests. There is no PostGIS.
MethodGeodesic (great-circle) distance on stored coordinates. Production uses MySQL’s sphere-distance function (or the same Haversine formula in SQL). Tests use the same formula in PHP. This is straight-line, not road miles and not drive time.
When coordinates are createdOnce, when the Professional origin or the event location is saved. Search and bidding never call a mapping service.
Indexing / speedSame-state filter first (already indexed), then a bounding box on coordinates, then the precise circle check on the remaining rows. Launch is seven jurisdictions. With indexes this stays interactive at thousands of Professionals and acceptable into the tens / low hundreds of thousands in one state.
Mapping API for matching?No.
API for saving an address?Yes — a geocoder on save only. Primary: U.S. Census Geocoder (no per-request fee). Optional paid Google only if Census fails and a launch key already exists. Never on every browse or bid.
CostsSearch: $0 per query. Census on save: $0 (public; rate-limited on write). Google fallback: only if switched on, billed per save. ZIP centre table: $0, public data for the seven launch states.
Trade-offsStraight-line is shorter than driving. A Professional 20 road-miles away via a river or beltway may be 12 miles as the crow flies (included) or the reverse (excluded). That is the V1 trade-off requested. This is not travel time and not a travel fee. Same-state still wins: a circle that overlaps a neighbouring state does not match that state’s events.
Not recommended for V1 matchingDriving / directions lookups on each search (cost, delay, third-party dependency).

No extra information is required to approve the method. The default radius in miles is Q5-A, not a Q6 question.

Q7 — Geocoding failure and ZIP fallback

Proposed hierarchy (not locked): precise validated location → validated ZIP fallback → unresolvable. Matching must be checked on both sides: Professional origin and event location.

Fact today: GigResource can map a ZIP prefix to a state, not a ZIP to a point. ZIP fallback requires a ZIP centre table. Until that exists, a ZIP is not a coordinate. The event location is still free text.

Silent eligibility is prevented by a hard gate: both sides must be exact or acceptable ZIP, both must have coordinates, same event state, and geodesic distance within radius. Unresolved or missing coordinates = not eligible. Tests must prove a failed geocode never appears in an in-range list.

NEED MORE INFORMATION (Q7-A): confirm or change the broad-ZIP cutoff (150 square miles / half of travel radius). Do not invent a different number without a stamp.
