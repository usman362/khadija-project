Brix Artwork Brief

GigResource · 12 October 2026 · For the designer producing the Brix character files
What this is. Brix the Badger is the GigResource mascot. There is one character per event type, and when a client posts an event and picks the type, that character stays with the event on every screen until the event is finished. There are 39 characters in all. Concept images exist for every one of them, but they are references only: the design is yours to draw.
This replaces the earlier version of this brief. That one asked for head-and-shoulders artwork only, and told you to hold back fifteen of the characters. Both of those have changed. All 39 are needed, and each one needs six views. Work from this document.

1. The character is yours to design

You are asked for an original, appealing badger with a personality that reads across many kinds of events. The concept images that came with this project show the idea; they are not a style to copy.

Artificial intelligence must not be used to generate, redraw, modify, enhance or complete any artwork or any part of it. Everything must be originally hand-drawn. Drawing digitally in ordinary illustration software is fine; AI image generation or AI editing is not. Please describe how you work, and include the editable original files.

2. Two samples get approved before anything else

Before producing any event characters, send two drawings of your proposed Brix:

  • a headshot, and
  • a full body, head to toe, including the whole tail.

GigResource reviews and approves both before the event artwork begins. Sending them is not approval. If changes are asked for, revise and send again.

3. Six views of every approved character

Once the base character is approved, each of the 39 events needs six separate images:

That is 39 characters × 6 views = 234 images. Worth being certain of before you quote.

The full-body canvas is taller than the headshot one on purpose. A standing badger with feet and a tail squeezed into a square ends up too small to use. Nothing may be cropped in the full-body views.

Proportions, badger features, clothing and the event accessories stay identical across all six. They are the same character looking a different way, not six designs.

4. The circles come off

Every concept image so far has the character sitting on a coloured circle, painted into the picture. Please send the character on its own, transparent, with no circle.

The website draws the circle itself, which means it can be tinted to match the page, the dark mode can treat it differently, and the same file works on a card, in a list, in the chatbot and on a confirmation screen without a second version.

Instead of drawing the circle, tell us the colour you intended. Section 7 explains the format.

 The dashed square is the file. The shaded circle is the one the website draws behind the character.

In the three headshot views, keep the character inside that circle. On small screens the site crops to it, so anything outside is cut off. The full-body views are not cropped to a circle, so they only need a small margin all round.

5. File specification

ItemWhat we need
FormatPNG with a real transparent background (alpha channel). Not a white background, and not JPG.
Size512 × 512 for the three headshots, 512 × 768 for the three full-body views.
EdgesClean anti‑aliased edges with no white fringe. A white outline is the commonest export mistake and it shows badly on a coloured circle.
WeightUnder roughly 150 KB for a headshot, 250 KB for a full body. A lot of them load on one page.
NamingThe character name from sections 8 and 9, then the view. For example BRIX-ID01-WEDDING-HEAD-C.png and BRIX-ID01-WEDDING-BODY-L.png. HEAD or BODY, then L, C or R. All capitals, hyphens, no spaces.
Also usefulA second set of the centre headshots at 128 × 128, in a folder called small. Helpful but not essential.
Source filesThe layered or vector originals, so new sizes can be made later without coming back to you.

6. Consistency across all 39

These sit next to each other in lists, so small differences are obvious. Please keep identical on every character:

  • the head at the same size and the same place on the canvas;
  • the same camera angle for each of the six views;
  • the same eye size and expression, except where a celebration pose is asked for;
  • the same line weight and level of detail.

Only the hat, the clothing and the props should change between characters, and those should say what the occasion is at a glance.

7. The colour codes we need back

Because the site draws the circle, the colour has to come as a code rather than a picture. For each of the 39 send either one flat hex code, for example #EA580C, or two if the circle is a gradient, the start and the end. 10. Two extra pieces, and five you do not need to draw

FileWhat it is
BRIX-GUIDEThe plain Brix with no hat and no props. Used for general help, the chatbot when it is not talking about a particular event, empty pages and error pages. Six views, same as the others.
BRIX-CELEBRATIONThe same plain Brix in a happy or celebrating pose, for the screen a client sees after a booking is confirmed. Centre views are enough.
A saving worth knowing about. The original guide also asked for a Brix per account type, in five colours. Because the site now draws the circle itself, those five do not need drawing. The plain Brix above, on a circle the site colours, covers all five. Five fewer characters for the same result.

11. Rules that must hold

  • Brix never replaces a real person's profile photo.
  • Brix never sits on or beside a price, a deposit, a balance, a signature or a payment button.
  • One event type has exactly one character. The six views are views, not alternates.
  • No numbers, dates or years on any character. One character serves every event of that type, so a number would be wrong most of the time.
  • The general Religious Ceremony character carries no symbol of any single faith. Particular faiths already have their own characters.
Do not draw a character for Memorial or Celebration of Life. The site offers that event type and will deliberately show no mascot on it. Those pages stay plain.

12. One correction to the keyword sheet

On the sheet of the eight newer characters, ID34 Quinceañera lists Sweet 16 among its keywords. Sweet 16 already belongs to ID08, and one event type can only have one character, so please drop Sweet 16 from ID34 and leave it with Quinceañera, Quince Party and 15th Birthday.

13. Delivery checklist

  • Two approval samples first: one headshot, one full body. Wait for approval.
  • Then the 24 characters in section 8, six views each, named as specified.
  • Then the 15 in section 9, the same way.
  • BRIX-GUIDE, and BRIX-CELEBRATION if it is a separate drawing.
  • The circle colours as hex codes, one line per id.
  • The layered or vector source files.
  • A note on how the artwork was made, confirming no AI was used.
